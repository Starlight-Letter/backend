# 별빛안부 기능 인수 점검표

기준일: 2026-10-07  
대상: React 프론트엔드 · Spring Boot API · PostgreSQL

## 판정 기준

- **통과**: 사용자 화면 또는 실제 HTTP 요청과 PostgreSQL 상태까지 확인했다.
- **실패**: 요구 결과와 다른 응답, 화면, 데이터가 확인됐다.
- **대기**: 실행 환경·운영 계정·외부 설정이 없어 아직 검증하지 못했다.
- 공개 전에는 **높음** 항목이 모두 통과해야 한다.

## 8. 2026-10-07 실제 실행 기록

- 테스트 환경: PostgreSQL(`starlight_test`)과 Spring Boot API(`127.0.0.1:3002`)를 연결해 HTTP 요청으로 확인했다.
- 통과 흐름: 비회원 공개 조회, 회원가입, 중복 닉네임 거부, 로그인·로그아웃, CSRF 거부, 편지 작성, 같은 요청 재시도, 요청 키 충돌, 반응·보관 토글, 중복 신고 거부, 주간·월간 베스트, 익명 서비스 문의, 없는 다리·편지 오류, 일반 회원의 운영 API 차단.
- 수정 사항: Origin·본문 크기 제한을 필터가 직접 반환할 때 UTF-8을 지정하지 않아 한글 오류 메시지가 깨지는 문제를 수정했고, 재검증했다.
- 계정 흐름: 복구 후 기존 세션·기존 비밀번호가 무효화되고, 비밀번호 변경 후 새 비밀번호만 로그인되며, 탈퇴 후 편지와 닉네임 표시는 남고 닉네임 재사용이 가능함을 확인했다.
- 신고 흐름: 기존 신고 1건이 있는 편지에 서로 다른 계정 4개가 추가 신고하자 5건째에 자동 숨김됐다. 보관한 계정에는 `지금은 볼 수 없는 편지`로 표시됐다.
- 운영자 흐름: 테스트용 운영자 계정을 프로비저닝하고 TOTP 로그인 뒤 질문·경고·문의·검사 규칙 조회를 확인했다. 프로비저닝 형식과 로그인 복호화 형식이 달라 로그인할 수 없던 결함을 통합 테스트로 재현해 수정했다.
- 운영자 변경: 신림교의 다음 주 월요일 질문을 등록·수정했고, 시작 편지를 등록·수정했다. 문의를 `in_progress`로 전환했고, 새 광고 문구 규칙은 신규 편지 작성에서 즉시 차단됐다. 자동 숨김 편지 복원 뒤 공개 상세 조회도 성공했다.
- 후속 확인: 문의를 `resolved`로 전환했고, 규칙 비활성화와 신고 편지의 숨김·숨김 유지·삭제도 성공했다. 시작 편지의 숨김·복원·삭제 API는 아직 없으므로 별도 구현 작업으로 남겼다.
- 자동 회귀: `TEST_DATABASE_URL`을 지정한 `./gradlew test --no-daemon --offline`, `npm test -- --run`(16개), `npm run build`가 모두 통과했다. 화면 시나리오 재검증은 아래 대기 항목과 함께 수행한다.
